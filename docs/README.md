# 프로젝트 문서

프로젝트의 구조와 개발 규칙을 역할별로 관리한다. 코드 가까이에 있어야 하는 에이전트 지침과 스크립트 설명은 기존 위치에 두고, 이 디렉터리에서는 사람이 탐색할 수 있는 진입점만 제공한다.

## 문서 분류

| 역할 | 설명 |
| --- | --- |
| [아키텍처](architecture/README.md) | 레이어 경계, 데이터 접근 및 공통 처리 흐름 |
| [보안](security/README.md) | 인증·인가와 접근 제어 경계 |
| [컨벤션](conventions/README.md) | 프로젝트 전반의 명명 및 작성 규칙 |
| [검증](validation/README.md) | 정적 검증과 테스트 전략 |

## 문서 배치 원칙

- 문서는 주제가 아니라 독자가 찾는 역할을 기준으로 한 곳에만 둔다.
- 다른 역할에서 같은 내용이 필요하면 복제하지 않고 대표 문서에 링크한다.
- 코드나 도구의 디렉터리 구조를 설명하는 문서는 코드 가까이에 유지한다.
- 작업 중간 산출물은 `_workspace/`에 유지하고, 지속적으로 유효한 규칙만 이곳으로 승격한다.
