# Promotion Image Create

Tie Knot 홈의 실제 프로모션 데이터와 히어로 소비 규격을 바탕으로, 사용자가 선택한
활성 프로모션의 무문자 배경 이미지를 만든다. 프로모션마다 전달할 가치에 맞는 독립된
연출을 사용하고, 승인된 최종 파일만 서비스 자산 경로에 저장한다.

## 범위

- 결과: 선택한 활성 프로모션별 최종 히어로 배경 이미지 1장
- 수정: 승인된 콘셉트를 유지한 부분 수정 또는 새 콘셉트 승인 후 재생성
- 저장: `public/assets/images/promotions/{promotion-id}.webp`
- 제외: 비활성 프로모션, 프로모션 카피 작성, `promotions.json` 수정, 컴포넌트 연결,
  상품 이미지, LiveDemo 이미지, 모바일 청첩장 내부 이미지, 미적·브랜드 품질 검증,
  점수 산정과 합격·불합격 판정

이 스킬은 이미지 생성과 사용자 승인까지만 담당한다. 생성한 세션이 결과물의 객관적
품질을 보증하지 않으며, 최종 이미지의 독립 검토는 별도 세션에서 수행한다.

## 입력과 실제 소비처

작업을 시작할 때 다음 순서로 현재 상태를 확인한다.

1. `src/app/(main)/_components/HomeTemplate.tsx`에서 실제로 import하는 히어로
   컴포넌트를 찾는다. 파일명을 추정하지 않는다.
2. 해당 컴포넌트에서 이미지 비율, `object-fit`, 오버레이 위치, 카피 영역과 반응형
   클래스를 확인한다.
3. `src/core/content/promotions.json`에서 활성 프로모션을 읽는다.
4. 사용자에게 생성할 활성 프로모션 ID를 선택받는다. 전체 활성 항목을 자동 생성하지
   않는다.
5. 선택한 프로모션마다 타깃 고객을 필수로 입력받는다.

프로모션의 제목, 설명, 배지와 CTA는 `promotions.json`을 기준 정보로 사용한다. 사용자
입력과 데이터가 충돌하면 생성 전에 어떤 정보를 우선할지 확인한다. 원하는 분위기,
금지 요소와 참고 이미지는 선택 입력으로 받는다.

스킬에 기록된 규격과 실제 소비처가 다르면 생성 전에 차이를 사용자에게 알리고 현재
소비처에 맞출지 확인한다.

## 공통 제작 조건

- 프로모션 하나당 반응형 전 구간에서 공유할 이미지 한 장만 만든다.
- 기본 원본은 가로 `3:2`다. 최종 파일은 반드시 `1920×1280` WebP, 품질 `80~85`,
  sRGB, 불투명 이미지로 출력한다.
- 생성 도구의 원본 크기와 관계없이 비율을 왜곡하지 않는 고품질 리샘플링으로
  `1920×1280` 표준 크기에 맞춘다. 원본 비율이 `3:2`가 아니면 핵심 피사체와 안전
  영역을 유지해 자른 뒤 리샘플링한다.
- 핵심 피사체는 중앙에서 약간 오른쪽, 높이의 중앙 부근에 둔다.
- 좌측 하단은 HTML 제목·설명·CTA가 올라오는 정돈된 배경으로 유지한다.
- 모바일 `4:5`부터 와이드 데스크톱 `3:1`까지의 `object-cover` 잘림에서 핵심 피사체가
  남도록 중앙 안전 영역을 사용한다.
- 이미지 안에 홍보 문구, 읽을 수 있는 생성 문자, 로고, 버튼, 배지, 워터마크를 넣지
  않는다.
- 투명 영역, 프레임, 이미지 자체의 둥근 모서리와 UI 장식은 넣지 않는다.

프로모션마다 피사체, 장소, 구도, 조명, 분위기와 강조 색상을 메시지에 맞게 다르게
설계한다. 여러 프로모션에 같은 색감이나 촬영법을 강제로 적용하지 않는다. 공통으로
유지할 것은 Tie Knot의 브랜드 금지 요소, 무문자 원칙, 반응형 안전 영역과 카피 회피
영역이다.

별도 지시가 없으면 현대적인 국내 웨딩 서비스 맥락을 사용한다. 한복이나 전통 예식
요소는 프로모션과 직접 관련되거나 사용자가 요청할 때만 사용한다. 기본 표현은 고급
웨딩 에디토리얼 사진으로 하되, 메시지를 더 정확히 전달할 근거가 있을 때만 일러스트,
3D 또는 콜라주를 콘셉트 후보로 제안한다.

다음 표현은 기본적으로 피한다.

- 과도한 분홍색과 광택, 과포화 색감
- 하트, 반지, 꽃잎을 상투적으로 남용한 연출
- 저가 웨딩 스톡 사진처럼 보이는 장면
- 프로모션 메시지와 관계없는 장식과 피사체

인물은 메시지에 필요할 때만 성인으로 표현하고 특정 실존 인물을 연상시키지 않는다.
기능 중심 프로모션은 손, 기기, 사진, 공간과 소품을 먼저 고려한다. 기기 자체는 사용할
수 있지만 생성 모델이 임의의 서비스 UI나 읽을 수 있는 화면 문자를 만들게 하지 않는다.
실제 서비스 화면이 필요하면 사용자가 제공한 스크린샷만 합성 대상으로 사용한다.

## 이미지 도구와 참고 이미지

- 생성과 편집에는 환경이 제공하는 전용 이미지 생성·편집 도구를 사용한다. HTML,
  SVG, CSS 필터나 일반 스크립트로 생성 이미지를 대신하지 않는다.
- 외부 레퍼런스는 사용자가 요청하거나 텍스트만으로 방향을 설명하기 어려울 때만
  탐색한다. 특정 작품이나 작가의 결과를 그대로 복제하지 않는다.
- 현재 임시 이미지와 과거 생성물을 자동으로 브랜드 기준 이미지로 간주하지 않는다.
  사용자가 적용 범위를 명시한 참고 이미지만 시각 입력으로 사용한다.
- 이미지 생성 도구를 사용할 수 없으면 콘셉트와 프롬프트까지만 제공하고, 파일을
  생성하거나 저장했다고 보고하지 않는다.

## 실행 절차

### 1. 대상과 브리프 확정

활성 프로모션 목록을 제시하고 생성할 ID를 선택받는다. 선택한 각 항목에 대해 타깃
고객을 반드시 확인한다. 데이터에 없는 연출 제약만 추가로 질문하고, 이미 확인 가능한
제목·설명·CTA를 다시 입력하게 하지 않는다.

### 2. 콘셉트 제안과 승인

선택된 모든 프로모션의 콘셉트를 먼저 함께 제안해 연출 중복을 드러낸다. 프로모션마다
서로 구분되는 완성 콘셉트 2~3개를 제안하며 각 안에 다음을 포함한다.

- 전달할 핵심 인상과 프로모션 메시지의 연결
- 장면, 핵심 피사체와 필요한 소품
- 표현 방식, 분위기, 조명과 강조 색상
- 좌측 하단 카피 회피 영역과 반응형 크롭 대응
- 인물, 기기 또는 실제 UI 자산의 사용 여부

사용자가 각 프로모션의 콘셉트를 선택하고 필요한 변경을 승인하기 전에는 이미지를
생성하지 않는다.

### 3. 이미지 생성과 수정

승인된 콘셉트마다 시안 한 장만 만들고, 프로모션을 한 항목씩 처리한다. 승인 전 시안은
임시 작업 위치에만 두며 서비스 자산 폴더에 저장하지 않는다.

사용자가 색감, 피사체 위치나 소품 같은 부분 수정을 요청하면 승인된 나머지 조건을
유지한 편집으로 처리한다. 장면, 표현 방식 또는 핵심 메시지가 달라지면 기존 시안을
누적 편집하지 않고 새 콘셉트로 다시 승인받은 뒤 생성한다.

### 4. 최종 저장

사용자가 최종 시안을 승인하면 다음 경로에 저장한다.

```text
public/assets/images/promotions/{promotion-id}.webp
```

같은 경로에 파일이 이미 있으면 덮어쓰기 전에 교체 승인을 받는다. 최종 파일 외의
시안이나 폐기본을 해당 디렉터리에 남기지 않는다. `promotions.json`, 컴포넌트 또는
다른 애플리케이션 파일은 수정하지 않는다.

## 확인과 검증 경계

저장 후 다음 사실만 기계적으로 확인한다.

- 파일이 보고할 경로에 존재한다.
- 실제 형식이 WebP다.
- 실제 해상도가 `1920×1280`이다.
- 색상 공간이 sRGB이고 투명 영역이 없다.

표준 크기 변환은 형식과 규격을 맞추기 위한 결정론적 처리이며 미적 품질 검증으로
간주하지 않는다.

이미지를 만든 세션에서는 미적 완성도, 브랜드 적합성, 메시지 전달력, 반응형 화면의
좋고 나쁨을 평가하거나 점수화하지 않는다. 자체 합격 판정이나 근거 없는 품질 보증도
작성하지 않는다.
