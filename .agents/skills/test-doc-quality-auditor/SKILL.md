# 테스트 문서 품질 감사

테스트 문서가 읽기 좋은지를 넘어, 서로 다른 개발자가 같은 결정을 내리고 실행 가능한 테스트를 작성하게 하는지 평가한다.

## 필수 절차

1. 감사 대상과 평가 목적을 확정한다. 별도 지시가 없으면 요청된 모든 테스트 문서를 하나의 문서 세트로 평가한다.
2. 저장소 지침과 테스트 관련 기준 문서를 모두 읽는다. 문서가 설정이나 명령을 주장하면 실제 설정 파일도 대조한다.
3. [고정 루브릭](references/rubric.md)을 끝까지 읽고 그대로 적용한다. 임의로 배점, 앵커, 상한을 바꾸지 않는다.
4. 각 지표를 독립적으로 0~4 수준으로 판정한 뒤 배점으로 환산한다. 먼저 총점을 정하고 근거를 끼워 맞추지 않는다.
5. 모든 감점에 파일과 줄 번호, 관찰 사실, 독자에게 미치는 영향을 연결한다. 취향이나 막연한 인상만으로 감점하지 않는다.
6. 치명 결함 게이트와 점수 상한을 마지막에 적용한다. 중복 감점은 하지 않는다.
7. 이전 평가가 제공되면 동일 루브릭으로 현재 문서를 새로 채점한 후 지표별 증감과 해결·잔존·신규 문제를 비교한다.

## 엄격성 원칙

- 문서에 명시되지 않은 내용은 독자가 추론할 수 있다고 가정하지 않는다.
- 의도, 향후 CI 변경, 구두 설명은 문서에 반영되어 있지 않으면 점수 근거로 인정하지 않는다. 단, 사용자가 평가 가정으로 명시하면 그 가정을 보고서에 적고 해당 범위에만 적용한다.
- 일반적인 모범 사례와 프로젝트 고유 사실을 구분한다. 프로젝트 사실은 저장소 증거로 검증한다.
- 같은 문제가 여러 지표에 영향을 주더라도 주된 지표에서만 감점하고, 다른 지표에는 교차 참조한다.
- 완전한 예제가 하나 있다는 이유로 전체 문서의 실행 가능성을 최고점으로 주지 않는다. 대표적인 계층과 경계 사례를 함께 본다.
- 문서 분량 자체에는 점수를 주지 않는다. 필요한 정보를 최소한의 중복으로 제공하는지를 본다.
- 요청이 평가뿐이면 문서를 수정하지 않는다.

## 필수 출력

다음 순서로 한국어 보고서를 작성한다.

1. **판정:** 총점, 등급, 승인 상태, 적용된 가정과 상한
2. **점수표:** 8개 지표의 수준, 환산 점수, 한 문장 근거
3. **치명 결함:** 해당 여부와 증거. 없으면 없다고 명시
4. **주요 발견:** 심각도순으로 파일·줄 근거, 영향, 최소 개선 조건
5. **시나리오 검증:** 루브릭의 대표 시나리오 결과와 합의 가능성
6. **개선 우선순위:** 같은 노력 대비 점수 상승이 큰 순서와 예상 상승 범위
7. **재평가 비교:** 이전 결과가 있을 때만 지표별 증감과 문제 상태

점수는 `획득/배점`으로 표시하고 산식을 검산한다. 근거가 부족하면 높은 점수를 추정하지 말고 보수적으로 채점한다.
