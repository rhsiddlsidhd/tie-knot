# 카테고리별 이미지 분석 프로필

이 문서는 분석 우선순위를 정한다. 카테고리와 서브카테고리의 유효한 값은 항상
`src/core/domain/product-category.ts`에서 확인한다. 아래 키는 현재 알려진 프로필이지
도메인 enum의 복사본이 아니다.

## 공통 원칙

- 제목은 `[이미지에서 도출한 고유 표현] [명확한 품목명]`을 기본으로 한다.
- 품목명은 사용자가 목록에서 상품 종류를 바로 식별할 수 있는 자연스러운 한국어다.
- 변형 폴더명이나 내부 코드를 제목 앞에 기계적으로 붙이지 않는다.
- 색, 소재, 규격, 구성, 기능은 이미지 문구나 사용자가 제공한 확정 사실이 있을 때만 쓴다.
- 가격, 할인, 배송, 재고, 인기, 판매량, 비교 우위는 카피에 넣지 않는다.
- 설명은 공백 포함 180~260자를 권장하고 최대 300자로 제한한다. 확인된 정보가 적으면
  더 짧게 쓸 수 있으며, 길이나 문장 수를 채우기 위해 반복하거나 추측하지 않는다.
- 3~4문장을 기본으로 하되 1~2문장도 허용한다.

## invitation

상품 유형은 기본적으로 `digital` 후보로 발표하고 사용자 확인을 받는다.

- wedding의 명확한 품목명: `모바일 청첩장`
- first-birthday의 명확한 품목명: 이미지에 따라 `모바일 돌잔치 초대장`을 우선 검토
- 우선 분석: 색상·타이포그래피·여백·장식·명시된 모션, 제공 콘텐츠, 모바일 구성,
  입력·미리보기·발행·공유 흐름
- 설명에 선택적으로 반영: 초대 메시지, 달력, 갤러리, 오시는 길, 방명록,
  연락처·계좌 안내처럼 실제 이미지에서 확인된 콘텐츠
- 설명에서 제외: 개인정보 공개 범위, 빈 정보 발행, 발행 취소 등 세부 운영 안내
- 변형 코드·기존 변형 표시명·영어 이름은 라우팅 근거일 뿐 제목 후보에 그대로 쓰지 않는다.

## favor

상품 유형은 기본적으로 `physical` 후보로 발표한다.

- 품목명: 현재 `subCategory` 한글 라벨을 중심으로 하되 이미지가 답례 용도를 명시하면
  `답례`를 자연스럽게 결합할 수 있다.
- 우선 분석: 실제 품목, 구성 수량, 크기·용량, 소재·향, 포장, 사용법, 답례 상황 적합성
- 주의: 외관만 보고 향, 원료, 연소 시간, 피부 효능, 식품 성분을 추측하지 않는다.

## accessory

상품 유형은 기본적으로 `physical` 후보로 발표한다.

- 우선 분석: 품목, 소재, 색상, 규격, 장식, 설치·착용·배치 방식, 함께 쓰는 대상
- 설명은 예식 공간이나 착용 장면과의 조화를 다룰 수 있지만 이미지 근거가 있어야 한다.
- 주의: 내구성, 알레르기 안전성, 수작업 여부를 외관만으로 단정하지 않는다.

## guestbook

상품 유형은 기본적으로 `physical` 후보로 발표한다.

- 우선 분석: 기록 방식, 제본·표지·내지, 페이지 또는 구성품, 사용 인원·배치 방식,
  보관성과 기념성 중 확인된 내용
- 주의: 종이 재질, 페이지 수, 잉크 호환성은 명시된 경우에만 사용한다.

## ceremony

상품 유형은 기본적으로 `physical` 후보로 발표한다.

- 우선 분석: 명확한 품목과 예식 중 용도, 구성품, 소재, 규격, 설치·배치·사용 방식,
  예식 동선이나 공간과의 적합성
- 주의: 안전성, 방염, 하중, 일회용·재사용 여부는 명시된 경우에만 사용한다.

## 전용 프로필이 없는 카테고리

- 사용자에게 전용 프로필이 없음을 알리고 범용 모드로 진행한다.
- 이미지에서 확인되는 품목, 색상, 형태, 구성품, 규격, 명시된 용도만 사용한다.
- 디지털·실물 유형은 경로와 이미지로 후보를 추론하되 반드시 사용자 확인을 받는다.
- 카테고리 특화 기능, 소재, 성능, 사용 효과를 추측하지 않는다.
