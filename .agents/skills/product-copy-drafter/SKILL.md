# Product Copy Drafter

Tie Knot의 로컬 상품 이미지에서 검수 가능한 `title` 후보와 `description` 초안을
만든다. 결과의 소비자는 자동화 시스템이 아니라 카피를 선택하는 사용자다.

## 범위

- 결과: 제목 후보 3개, 공통 설명 1개, 근거, 루브릭 점수, 실제 경고
- 제외: 이미지 생성·수정, Cloudinary 업로드, 관리자 폼 조작, 가격·할인 결정,
  파일 저장, `products.json`, DB 조회·삽입·수정
- 기본 출력은 대화형 한국어 보고서다. 사용자가 별도로 요청할 때만 JSON으로 변환한다.

## 입력 계약

대상 이미지 디렉터리 경로를 반드시 받는다. 저장소나 상위 디렉터리를 자동으로
탐색하지 않는다. 프로젝트 외부 절대경로와 프로젝트 내부 경로를 모두 허용한다.

지원 파일은 `webp`, `png`, `jpg`, `jpeg`다.

```text
{asset-directory}/
├── thumbnail.{supported-extension}
└── detail-page/
    ├── 01-{role}.{supported-extension}
    ├── 02-{role}.{supported-extension}
    └── ...
```

- 루트의 `thumbnail.*`은 정확히 1장이어야 한다. 없거나 여러 장이면 중단한다.
- `detail-page/` 바로 아래에서 `NN-{role}.*`만 읽고 두 자리 번호로 정렬한다.
- 재귀 탐색, PSD, PDF, GIF, 영상, 임시·원본 편집 파일은 처리하지 않는다.
- 상세 이미지 없음, 중복 번호, 번호 누락, 손상 파일은 정확히 보고한 뒤 계속할지 묻는다.
  사용자가 계속하면 실제 문제만 최종 `warnings`에 남긴다.

## 실행 절차

### 1. 분류 후보 확인

1. 전달받은 경로와 파일 구성을 검사한다.
2. `src/core/domain/product-category.ts`를 끝까지 읽어 현재 유효한 `category`,
   `subCategory`, 한글 라벨을 확인한다. 스킬에 적힌 카테고리 예시를 enum의
   원본으로 사용하지 않는다.
3. 경로 세그먼트에서 `category`, `subCategory`, 변형 식별자를 추론한다. 경로만으로
   부족하면 썸네일 한 장을 분류 목적으로만 확인할 수 있다.
4. 아래 내용을 한 번 발표하고 사용자의 확인을 기다린다. 자동 확정하지 않는다.

```text
이미지 경로:
추론한 category:
추론한 subCategory:
추론한 상품 유형: digital | physical
썸네일:
상세 이미지 수와 순서:
파일 구성 문제:
```

### 2. 이미지 근거 추출

사용자 확인 후 썸네일과 모든 상세 이미지를 직접 확인한다. 대표 이미지만 보고
나머지를 추측하지 않는다. 다음 사실 장부를 내부적으로 만든다.

- 시각 사실: 색, 형태, 질감, 타이포그래피, 여백, 장식, 이미지에 명시된 움직임
- 상품 사실: 품목, 구성품, 소재, 규격, 용량, 기능, 용도 중 이미지에서 확인된 것
- 이용 사실: 입력·사용·관리 흐름 중 이미지에 명시된 것
- 제외 정보: 판매 조건, 운영 안내, 개인정보 안내, 주의사항처럼 짧은 상품 카피에
  부적합한 내용
- 불확실성: 읽을 수 없는 문구, 이미지 간 충돌, 근거가 없는 주장

정지 이미지에 움직임이 있다고 임의로 추론하거나, 보이는 외관만으로 소재·향·성능을
단정하지 않는다. 사용자가 별도로 제공한 확정 사실은 이미지 사실과 구분해 사용할 수 있다.

### 3. 카테고리 관점 선택

[카테고리 프로필](references/category-profiles.md)을 끝까지 읽고 일치하는 프로필을
적용한다. 현재 도메인에는 있지만 전용 프로필이 없으면 그 문서의 범용 폴백을 사용한다.
전용 프로필 부재만으로 중단하지 않는다.

### 4. 후보 생성과 검수

[카피 루브릭](references/copy-rubrics.md)을 끝까지 읽는다.

1. 이미지에서 도출한 고유 표현과 명확한 품목명을 결합해 제목 후보군을 만든다.
2. 모든 후보에 필수 게이트를 적용한다. 하나라도 실패하면 점수화하지 않는다.
3. 통과 후보의 제목 루브릭을 채점한다.
4. 각 전문 영역이 배점의 60% 이상이고 총점이 80점 이상인 후보만 남긴다.
5. 총점 상위 3개를 선택한다. 동점은 MD, SEO, 브랜드, 디자인 점수순으로 결정한다.
6. 통과 후보가 3개 미만이면 새 후보군 생성과 평가를 최대 3라운드까지 수행한다.
7. 3라운드 뒤에도 부족하면 기준을 낮추거나 미달 후보를 섞지 않고 통과 후보만 발표한다.
8. 제목과 독립적인 공통 설명 초안 하나를 작성하고 설명 게이트와 루브릭을 적용한다.
   설명도 실패하면 최대 3라운드까지 다시 작성하며 기준을 낮추지 않는다.

기존 상품명 목록을 사용자가 제공하면 중복·혼동 가능성을 검토한다. 제공하지 않으면
운영 DB를 조회하지 않고, 보고서에 `운영 DB 기존 제목과의 중복은 확인하지 않음`을
검증 범위로 명시한다. 이것은 오류 경고가 아니다.

### 5. 초안 보고

다음 순서로 간결하게 발표한다.

1. 확인된 분류와 이미지 구성
2. 카피에 사용한 핵심 사실
3. 제목 후보 표: 순위, 제목, MD, 브랜드, 디자인, SEO, 총점, 한 줄 근거
4. 공통 설명 초안과 공백 포함 글자 수
5. 설명 점수표와 한 줄 평가
6. 이미지별 핵심 근거
7. 실제 경고와 검증 범위
8. `1·2·3 중 선택하거나 수정 방향을 알려 달라`는 질문

내부 탈락 후보, 숨은 사고 과정, 점수 계산을 위한 장황한 독백은 출력하지 않는다.

### 6. 사용자 선택 후 종료

선택된 제목과 설명의 어휘 중복을 다시 검사한다. 필요한 경우 설명만 최소 조정하고,
조정 폭이 의미를 바꾸면 설명 루브릭을 다시 채점한다. 최종 `title`, `description`,
각 글자 수를 명확히 발표하고 종료한다. 사용자가 요청하지 않은 파일이나 외부 상태를
변경하지 않는다.
