# Physical Product Thumbnail

Tie Knot에서 판매할 물리 상품의 외형을 정의하고, 승인된 외형을 유지한 상품
썸네일 한 장을 생성한다. 상품 설명만 주어져도 시작할 수 있지만, 사용자가 제공한
사실과 자산을 임의로 바꾸지 않는다.

## 범위

- 결과: 상품 외형 명세, 기준 이미지, 연출안 3개, 최종 썸네일 1장, 생성 명세
- 수정: 승인된 외형과 연출을 유지하며 사용자가 요청한 요소만 변경
- 제외: 모바일·디지털 상품, 상세 이미지, 프로모션 배너, 상품 카피, 업로드·DB 작업,
  품질 점수·합격 판정
- 별도 검수 에이전트가 판단할 수 있도록 승인 조건과 실제 생성 기록만 남긴다. 이
  스킬이 자체 점수나 합격 판정을 작성하지 않는다.

## 필수 참고 문서

작업 시작 시 다음 문서를 끝까지 읽는다.

- [사이트 시각 기준](references/site-visual-guide.md): 출력 비율, 화면 재사용 위치,
  UI 회피 영역과 색상 기준
- [공통 촬영 기준](references/photography-guide.md): 모든 물리 상품에 공유할 색감,
  조명, 그림자, 여백, 소품 원칙
- [생성 명세 작성 가이드](references/generation-spec-guide.md): 생성 전부터 갱신할 명세
  형식과 저장 경로

연출안 작성 직전에 [연출 요소](references/direction-elements.md)를 끝까지 읽고 14개
요소를 빠짐없이 검토한다.

참고 문서에 기록된 사이트 분석은 매번 반복하지 않는다. 사용자가 사이트 변경이나
기준 갱신을 요청했거나, 실제 코드와 문서가 충돌한다는 근거를 발견했을 때만 현재
화면을 다시 조사하고 기준 문서를 갱신한다.

## 입력 계약

최소 입력은 생성할 물리 상품의 종류 또는 설명이다. 다음 정보는 제공된 만큼
사용하고, 빠진 외형 정보는 제안 대상으로 분류한다.

- 상품 종류·용도
- 형태·비율·크기
- 재질·표면·색상
- 판매 단위·구성품·포장 상태
- 강조할 특징
- 고객층·가격대·원하는 인상
- 선호 참고 이미지와 참고할 범위
- 피할 표현
- 브랜드명·로고·라벨 자산과 정확한 문구

브랜드명·로고·라벨 문구는 사용자가 제공한 것만 반영한다. 제공되지 않은 브랜드나
읽을 수 없는 장식 문자를 만들지 않는다. 참고 이미지는 색감·구도·재질 등 적용할
범위를 구분해 기록하고 복제 대상으로 취급하지 않는다.

상품 식별자 `{product-slug}`가 없으면 상품을 식별할 수 있는 lowercase-kebab-case
후보를 제안해 확인받는다.

## 산출물

```text
public/images/products/{product-slug}/thumbnail/
├── reference.png
└── thumbnail.webp

docs/image-generation/{product-slug}/
└── generation-spec.md
```

- `reference.png`: 단색 배경, 소품 없는 상품 단독 기준 이미지
- `thumbnail.webp`: 승인한 연출을 적용한 세로형 `1:1.618` 최종 이미지
- `generation-spec.md`: 적용 기준, 승인 내용, 프롬프트, 참조 이미지와 수정 기록

파일을 생성하기 전에 예정 경로를 명세에 기록한다. 이미지 도구가 다른 형식으로
반환하면 시각 내용을 바꾸지 않는 형식 변환과 크기 조정만 수행해 위 경로에 저장한다.

## 이미지 도구

- 기준 이미지와 최종 썸네일 생성, 이후 수정에는 환경이 제공하는 전용 이미지
  생성·편집 도구를 사용한다. HTML·SVG·CSS 필터나 일반 스크립트로 생성 이미지를
  대신하지 않는다.
- 기준 이미지는 승인된 텍스트 외형 명세와 사용자가 제공한 시각 자산을 입력으로 삼는다.
- 최종 썸네일에는 승인된 `reference.png`를 참조 이미지로 전달한다. 수정할 때도 수정
  대상 이미지와 외형 기준 이미지를 함께 전달해 요청받지 않은 부분을 유지한다.
- 생성 후 실제 파일을 열어 경로, 크기, 형식과 대상 이미지가 맞는지 확인한다. 이 확인은
  산출물 식별 확인이며 품질 점수나 합격 판정이 아니다.
- 사용할 수 있는 이미지 생성 도구가 없으면 프롬프트와 명세까지만 작성하고, 이미지를
  생성하거나 저장한 것처럼 기록하지 않는다.

## 실행 절차

### 1. 작업 시작과 명세 생성

1. 물리 상품 썸네일 작업인지 확인한다. 모바일·디지털 상품이면 이 스킬로 진행하지
   않는다.
2. 사용자 입력을 제공 사실, 제공 자산, 미정 정보로 구분한다.
3. 생성 명세 가이드의 템플릿으로
   `docs/image-generation/{product-slug}/generation-spec.md`를 만들고 진행 단계가 바뀔
   때마다 갱신한다.
4. 사이트 시각 기준과 공통 촬영 기준에서 이번 생성에 적용할 조건을 명세에 기록한다.

### 2. 상품 외형 승인

1. 사용자가 지정한 외형은 그대로 유지한다.
2. 미정인 형태·재질·색상·크기·구성품·포장은 상품의 용도와 제작 가능성을 고려해
   제안한다. 제안을 사용자 제공 사실처럼 기록하지 않는다.
3. 형태, 재질, 색상, 크기, 판매 구성, 포장, 표면 문자, 강조 특징을 표로 제시하고
   승인을 기다린다.
4. 승인된 텍스트 명세로 단색 배경·소품 없는 상품 단독 기준 이미지를 생성한다.
5. 기준 이미지를 제시하고 외형 승인을 기다린다. 수정 요청이 오면 지적된 외형만
   변경하고 나머지는 유지한다.

텍스트 명세와 기준 이미지가 모두 승인되기 전에는 연출안을 확정하거나 최종
썸네일을 생성하지 않는다.

### 3. 연출안 3개 제안과 승인

승인된 동일 상품에 대해 서로 구분되는 완성 연출안 A·B·C를 제안한다. 각 안은 14개
연출 요소 전체를 하나의 콘셉트로 조합한다. 요소마다 선택지 3개를 따로 나열하지 않고,
차이가 없는 요소를 억지로 다르게 만들지 않는다.

각 안에 다음을 포함한다.

- 콘셉트와 전달할 인상
- 상품 특징을 보여주는 핵심 차이
- 14개 연출 요소의 적용값
- 공통 촬영 기준을 유지하는 부분과 상품 특성 때문에 조정하는 부분
- 소품과 판매 구성품의 구분
- 사이트 안전 영역과 정사각형 잘림 대응

사용자가 한 안을 선택하고 필요한 요소를 수정한 뒤 승인할 때까지 생성하지 않는다.

### 4. 최종 썸네일 생성

1. 승인된 `reference.png`를 외형 참조로 사용한다.
2. 승인된 연출안과 사이트 시각 기준을 이미지 생성 프롬프트에 명시한다.
3. 최종 이미지는 한 장만 생성한다.
4. 상품 핵심 형태와 강조 특징을 안전 영역에 둔다. 목록 카드의 상단 배지, 하단
   그라데이션·문구, `1.06` 확대와 상세 화면의 정사각형 잘림을 함께 고려한다.
5. 상품명이나 홍보 문구를 이미지 위에 넣지 않는다. 상품 표면 문자는 사용자가
   제공한 정확한 자산·문구만 사용한다.
6. 연출 소품은 판매 구성품과 명확히 구분하고 상품보다 강조하지 않는다.
7. 생성에 실제 사용한 프롬프트, 도구, 참조 이미지, 실제 크기·형식·경로를 명세에
   기록한다. 확인할 수 없는 모델명·시드·설정은 추정하지 않는다.

### 5. 수정

사용자가 수정할 요소를 지정하면 상품 외형, 승인된 다른 연출 요소, 출력 조건을 유지한
편집 요청으로 처리한다. 전체 재구성은 사용자가 명시적으로 새 연출을 요청한 경우에만
한다. 수정 차수마다 요청, 변경 요소, 유지 조건, 프롬프트, 결과 경로를 명세에 기록한다.

## 종료 보고

다음 항목만 간결하게 보고한다.

- 최종 썸네일과 기준 이미지
- 적용한 연출안과 사용자 수정 사항
- 생성 명세 경로
- 별도 검수에 전달할 파일 경로

검수 점수, 합격 여부, 근거 없는 품질 보증은 보고하지 않는다.
