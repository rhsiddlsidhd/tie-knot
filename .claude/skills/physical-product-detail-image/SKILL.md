# Physical Product Detail Image

Tie Knot 물리 상품의 구매 판단에 필요한 정보를 하나의 흐름으로 설계하고, 제품 촬영
소스와 정확한 한글 정보를 결합한 상세 이미지 패널을 실제 파일로 만든다. 프롬프트는
생성 기록일 뿐 산출물이 아니다.

## 범위

- 결과: 무문자 제품 촬영 소스, 조판 원본, 순서가 보장된 상세 이미지 패널, 생성 명세
- 수정: 승인된 제품 정체성과 요청받지 않은 패널 요소를 유지한 부분 수정
- 제외: 상품 외형 설계, 썸네일, 모바일·디지털 상품 이미지, 프로모션 배너, 상품 카피만
  작성하는 작업, 업로드·DB 작업, 상세페이지의 더보기 UI 구현
- 외형이나 기준 썸네일이 확정되지 않았으면 먼저 `physical-product-thumbnail` 작업이
  필요하다고 알린다. 이 스킬 안에서 새 상품 외형을 임의로 설계하지 않는다.

## 필수 참고 문서

작업 시작 시 다음 문서를 끝까지 읽는다.

- [패널 제작 기준](references/panel-production-guide.md): 7개 패널의 역할, 조판과 출력 기준
- [생성 명세 가이드](references/detail-image-spec-guide.md): 진행 기록과 산출물 경로

대상이 기존 상품 레시피와 일치할 때만
[상품별 촬영 제약](references/product-shot-constraints.md)에서 해당 항목을 읽는다. 다른
상품에 기존 레시피를 억지로 적용하지 않는다.

## 입력 계약

최소 입력은 상품을 식별할 수 있는 설명과 승인된 기준 이미지다. 다음 정보를 실제
판매 사양이나 사용자 제공 자료에서 확인한다.

- 정식 상품명과 상품 식별자 `{product-slug}`
- 승인된 기준 이미지 또는 최종 썸네일 경로
- 핵심 가치와 근거가 확인된 장점
- 구성품 명칭과 정확한 수량
- 소재, 제조 방식, 색상과 옵션
- 실제 측정 규격과 법정 계량 단위
- 사용 절차와 관리·보관·안전 주의사항
- 배송·교환·반품 정책
- 식품·화기·금속 등 상품 유형별 법정 고지

사용자가 제공한 사실, 이미지로 확인한 시각 사실, 미확정 정보를 구분한다. 보이는
외관만으로 소재·성능·인증·원산지·수치를 단정하지 않는다. 미확정 항목은 명세에
기록하고 패널에서 제외한다. 미확정 정보 때문에 패널 하나가 의미를 잃거나 안전·법적
오해가 생기면 최종 렌더링 전에 필요한 사실을 요청한다.

## 산출물

```text
public/images/products/{product-slug}/detail-page/
├── sources/
│   ├── 01-complete.webp
│   ├── 02-material.webp
│   └── 03-use.webp
└── panels/
    ├── 01-hero.webp
    ├── 02-benefits.webp
    ├── 03-components.webp
    ├── 04-material.webp
    ├── 05-size.webp
    ├── 06-usage.webp
    └── 07-notice.webp

docs/image-generation/{product-slug}/
├── detail-image-spec.md
└── detail-page-source/
    └── {조판 원본 파일}
```

- 촬영 소스가 이미 있으면 검증한 뒤 재사용하고 불필요하게 다시 생성하지 않는다.
- 패널은 기본 7개이며, 사실 부족으로 역할을 충족할 수 없는 패널은 빈 이미지나
  임시 문구로 만들지 않는다. 사용자와 보완 또는 제외를 확정해 명세에 남긴다.
- 조판 원본은 사용한 방식에 맞는 HTML/CSS, 디자인 파일 또는 무손실 원본으로 보존한다.
- 다른 저장 경로를 사용자가 지정하면 그 경로를 우선하고 명세에 기록한다.

## 이미지 및 조판 도구

- 무문자 촬영 소스 생성과 편집에는 환경이 제공하는 전용 이미지 생성·편집 도구를
  사용한다. 승인된 기준 이미지를 매번 제품 정체성 참조로 전달한다.
- 한글 카피, 숫자, 규격, 수량, 표, 주의사항은 이미지 생성 모델로 그리지 않는다.
  HTML/CSS 또는 글자를 정확히 렌더링할 수 있는 디자인 도구로 결정론적으로 조판한다.
- 환경에 이미 있는 렌더러와 프로젝트 의존성을 우선 사용한다. 상세 이미지 하나를
  위해 제품 런타임 의존성을 추가하지 않는다.
- 이미지 생성 도구나 결정론적 조판·렌더링 수단이 없으면 실제 이미지를 만든 것처럼
  보고하지 않는다. 가능한 단계와 막힌 산출물을 정확히 구분한다.

## 실행 절차

### 1. 입력 확인과 명세 시작

1. 물리 상품 상세 이미지 작업인지 확인한다.
2. 기준 이미지와 상품 정보를 제공 사실, 시각 사실, 미확정 정보로 분류한다.
3. 생성 명세 가이드에 따라 `detail-image-spec.md`를 만들고 단계마다 갱신한다.
4. 예정된 산출물 경로와 재사용할 기존 촬영 소스를 기록한다.
5. 제품 정체성이나 구매 판단에 필요한 사실이 불명확하면 생성 전에 확인한다.

### 2. 무문자 촬영 소스 준비

기존 소스가 각 역할을 충족하는지 먼저 확인하고 부족한 이미지만 만든다.

1. `01-complete`: 판매 구성 전체와 정확한 수량
2. `02-material`: 핵심 소재·구조·마감의 근접 표현
3. `03-use`: 실제 사용 또는 배치 방식

모든 소스에서 기준 이미지의 디자인, 비율, 재질 인상, 색상, 장식과 구성품 수를
유지한다. 상품이 요구하지 않으면 사람·손·생활 공간을 넣지 않는다. 읽을 수 있는 문장,
규격, 로고, 브랜드명, 라벨, 워터마크와 무의미한 생성 문자를 넣지 않는다.

생성 직후 각 파일을 직접 열어 다음을 확인한다.

- 기준 이미지와 같은 상품인지
- 구성품 수와 구조가 정확한지
- 중복·융합·누락·변형이 없는지
- 조판에 사용할 충분한 여백과 해상도가 있는지

문제가 있는 소스만 수정하고 승인된 다른 요소는 유지한다.

### 3. 패널 콘텐츠 확정

패널 제작 기준에 따라 확인된 사실을 7개 역할에 배치한다. 같은 정보를 여러 패널에
반복하지 않고, 핵심 소개에서 구매 전 확인 사항으로 자연스럽게 이어지게 한다.

조판 전에 다음을 내부 장부로 확정한다.

- 패널별 사용할 촬영 소스와 자르기 범위
- 정확한 제목, 본문, 수치와 단위
- 판매 구성품과 연출 소품의 구분
- 패널에서 제외한 미확정 항목
- 이미지 밖의 접근 가능한 텍스트로도 제공해야 할 핵심 정보와 법적 고지

### 4. 결정론적 조판과 렌더링

1. 기준 폭 860px에서 공통 배경색, 서체, 여백과 컬러 토큰을 정한다.
2. 제품 사진과 확정 문구를 조판 원본에 배치한다.
3. 패널 높이는 내용에 맞게 정하고 고정 3:4 비율로 강제하지 않는다.
4. 본문, 규격과 주의사항이 모바일 축소 화면에서도 읽히는 크기로 렌더링한다.
5. 7개 패널을 개별 WebP로 출력한다.
6. 실제 사용한 원본, 도구, 출력 크기와 경로를 명세에 기록한다.

### 5. 검수와 수정

모든 출력 파일을 직접 열고 다음을 확인한다.

1. 기준 이미지와 촬영 소스·패널의 제품 정체성이 같다.
2. 수량·소재·규격·문구가 확정 정보와 일치한다.
3. 패널 순서가 소개에서 구매 판단까지 자연스럽다.
4. 모바일 축소 상태에서 본문과 규격을 읽을 수 있다.
5. 패널 경계의 배경색, 여백과 시각 리듬이 자연스럽게 이어진다.
6. WebP의 실제 크기·형식·육안 품질과 파일 크기가 적절하다.
7. 사실과 다른 기능·인증·원산지·소재·수치, 생성 문자가 없다.
8. 핵심 정보와 법적 고지가 이미지에만 갇히지 않도록 구현 전달 사항이 명세에 있다.

수정 요청이 오면 지정된 요소만 바꾸고 제품 정체성, 확정 정보, 공통 토큰과 나머지
패널은 유지한다. 수정 내용과 결과를 명세에 추가한다.

## 종료 보고

다음 항목을 간결하게 보고한다.

- 촬영 소스와 최종 패널 경로
- 실제 생성·재사용·제외한 항목
- 조판 원본과 생성 명세 경로
- 미확정으로 제외한 정보
- 웹 적용 시 이미지 밖에도 제공해야 할 핵심 정보와 법적 고지

프롬프트만 제시하고 완료로 보고하거나, 파일을 열어보지 않은 채 품질을 보증하지 않는다.
